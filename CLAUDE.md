# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

`flutter`/`dart` are **not on PATH** here; Flutter is managed by fvm. Prefix commands with `export PATH="$HOME/fvm/default/bin:$PATH" &&`.

```bash
flutter pub get
flutter run
flutter analyze                      # also run by CI before building
dart run build_runner build --delete-conflicting-outputs   # regenerate drift/freezed/json code
flutter test                         # single file: flutter test test/foo_test.dart
flutter run --dart-define=PROXY_URL=http://127.0.0.1:8787   # app against a local Worker (`cd worker && npx wrangler dev`)
(cd worker && npm test)              # Cloudflare Worker tests (node:test, no dependencies)
# Android locally: needs a dummy android/key.properties (gitignored) and JDK 21 for Gradle (Flutter picks Java 25, which Gradle 8.14 rejects), see REVIEW.md M11
```

- Generated files (`*.g.dart`, `*.freezed.dart`) are **committed**. After editing a drift table, a `@freezed` class or a `@JsonSerializable` model, re-run `build_runner` and commit the output.
- All tests pass (`flutter test`; the failing counter template `widget_test.dart` was deleted, REVIEW.md B2). Examples of the style: `test/game_remote_data_source_test.dart` (`MockClient`) and `test/app_database_test.dart` (in-memory Drift); run one by path.
- CI is Codemagic ([codemagic.yaml](codemagic.yaml)): every push to `main` analyzes, runs `flutter test`, builds APK/AAB/iOS, then tags `v<pubspec version>` and publishes a GitHub release (deleting and recreating the tag if it already exists). Bump `version:` in `pubspec.yaml` to cut a new release (the Settings page reads the version from the build with `package_info_plus`, it is not written anywhere else).

## Architecture

Feature-first Clean Architecture under `lib/features/<feature>/{data,domain,presentation}` (account, game, settings, stats), plus `lib/core` for shared code. State management is `flutter_bloc` Cubits; navigation is `go_router`; DI is `get_it`.

**Dependency wiring is manual** in [lib/core/di/injection_container.dart](lib/core/di/injection_container.dart) (`sl`). Data sources and repositories are lazy singletons registered by interface; Cubits are `registerFactory` and take dependencies positionally via `sl()`. Adding a constructor parameter to a Cubit/repository means updating this file too. `main()` awaits `di.init()` before `runApp`.

**Global Cubits** (`GameCubit`, `AccountCubit`, `SettingsCubit`, `PsnCubit`) are provided once in [lib/main.dart](lib/main.dart); `ExploreCubit`, `StatsCubit` and `GameDetailsCubit` are provided per-route in [lib/core/router/app_router.dart](lib/core/router/app_router.dart). Routes use a `StatefulShellRoute.indexedStack` for the three bottom-nav tabs (`/games`, `/explore`, `/stats`); `/accounts`, `/credits`, `/category/:tagId` and `/gamesDetails/:appId/:fromExplorer` sit outside the shell. A page with nothing to show uses the shared `EmptyState` (`lib/core/widgets/empty_state.dart`: round icon, large title, body text and `EmptyStateAction` buttons), so the empty Library and Stats look the same.

**Local-first data.** Drift/SQLite ([lib/core/database/app_database.dart](lib/core/database/app_database.dart): `Games`, `Trophies`, `Activities`, `SteamCatalog`) is the source of truth; the UI reacts to `GameRepository.watchLibrary()` streams. Changing a table requires bumping `schemaVersion` and adding a migration step in the same file, **but not yet**: schema 3 is the baseline until a build is shared with testers (decided 2026-11-21, see REVIEW.md V4); until then change the tables directly, regenerate, and the user reinstalls. A game is identified by a `GameKey(platform, code)` ([lib/features/game/domain/entities/game_key.dart](lib/features/game/domain/entities/game_key.dart); `GamePlatform.steam`/`psn`, `code` is the Steam app id or the PlayStation `npCommunicationId`, as text): `Games` is keyed by `(platform, code)`, `Trophies` and `Activities` point to it with `(game_platform, game_code)`, and the details route is `/gamesDetails/:platform/:code/:fromExplorer` (`gameRouteParams`/`gameKeyFromRoute` in `core/router/game_route.dart`). PlayStation games (`GamePlatform.psn`, `platformSource` `'psn'`) are synced by `PsnRepository` (`lib/features/psn`: the Worker's `/psn/*` calls, the renewal token in secure storage, an incremental sync, `gameFromPsn` as the mapper; driven by the global `PsnCubit` and shown by `PsnConnectionTile` in the Settings page's "Connections"; see [docs/features/psn.md](docs/features/psn.md)); their trophies carry `type`, `hidden` and `rarity`, and a hidden unearned one shows as "Hidden trophy" until tapped. Only Steam games reach the Steam-only Worker calls (covers, rarity, details), which still take the integer id. `Game.platformSource` (`'local'` vs `'steam'`) and `isSynced` distinguish manually-added games from ones imported from a Steam account — logout deletes only `steam` + `isSynced` rows.

**Backend proxy.** Its source is in [worker/](worker/) (deployed by hand with `cd worker && npx wrangler deploy`; `wrangler.jsonc` declares the `KV` binding and `STEAM_API_KEY` is a secret configured on Cloudflare, not in the repo). A change to the token/login protocol must ship app and Worker together. The PlayStation routes (`/psn/*`, in `worker/src/psn.js`: authorize, login, refresh, profile, titles, trophies) are POST-only with every token and code in the body; the Worker must never call `console` and `invocation_logs` stays `false` in `wrangler.jsonc`, so no user data reaches the logs (tests enforce both). Every route is guarded by a per-client rate limit chosen in `worker/src/limits.js` (`TIERS`, bindings `RL_*` in `wrangler.jsonc`, answer `429 rate_limited`); a new route must be added to `TIERS` or to `UNLIMITED` or a test fails, and the limits must stay above what a real sync does (see [docs/features/rate-limiting.md](docs/features/rate-limiting.md)). Steam answers that are the same for everyone (`/game`, `/achievements`, `/rarity`, `/covers`, `/category`, `/catalog`) are kept in Cloudflare's cache through `shared(TTL.x)` in `worker/src/cache.js` (only successful answers, `X-Cache` shows HIT/MISS); never use it for a route with a session token or user data (`/library`, `/user`, `/playerAchievements`) or for `/psn/*` (tests enforce it). Cover art: Steam's default `library_600x900_2x.jpg` is a grey placeholder (HTTP 200) for many recent games, so the real URL comes from the Worker's `/covers` route and `GameCover` falls back through the other Steam images. The trophy rarity shown on the game page comes from the Worker's `/rarity` route. The genre tiles in Explore open a page fed by the Worker's `/category` route, which only accepts the tag ids in `CATEGORY_TAGS` (kept in sync with `exploregames/categories.dart` by a test). All remote calls (catalog, game details, user info, Steam login) go through a Cloudflare Worker whose base URL is hardcoded twice in `injection_container.dart`. The app never talks to Steam directly and holds no Steam API key. The Steam catalog is bulk-downloaded once into `SteamCatalog` (first 8 chunks synchronously, the rest in a fire-and-forget background task in `GameRepositoriesImpl`) and searched offline.

**Steam login / deep links (PKCE).** `AccountRepositoryImpl.startLogin()` generates a `Pkce` pair (`core/utils/pkce`), stores the verifier in secure storage and `AccountCubit.login()` opens `<proxy>/auth/steam?challenge=...` in the external browser. After Steam, the Worker redirects to `https://<worker>/open?code=...`, which reaches the app as that App Link or as `trophiestracker://stats?code=...`. `AccountCubit._handleDeepLink` hands the one-time code to `finishLogin`, which exchanges it with the saved verifier (`POST /auth/token`) for the session token; a link with no login in progress is ignored. The token is kept only in `FlutterSecureStorage` (never in SharedPreferences, nor in the cached profile) and sent as `Authorization: Bearer`; logout also calls `POST /logout`. `AppRouter.redirect` just rewrites the callback to `/accounts?sync=true`, which triggers the library sync once the cubit is authenticated. Never put the token in a route, URL or log line.

`GameRepositoriesImpl` caches un-authenticated remote game details in memory (`_cachedGames`); token-authenticated fetches (which include the user's achieved state) bypass the cache.
